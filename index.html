Readable code, not just working code

A sample from the event system: picking the next big event by weight, skipping recent ones and anything that clashes with an event already running.

Every module is split server/client, with config tables at the top so values can be tuned without digging through logic.

ServerScriptService/RoundEvents.lua

-- pick a big event: not in skip, not clashing with active ones;
-- boost = id that gets double weight (won the vote)
function Events.Pick(skip, active, boost)
	if type(skip) == "string" then skip = { [skip] = true } end
	skip = skip or {}; active = active or {}
	local pool, total = {}, 0
	for _, e in ipairs(Events.List) do
		local ok = not skip[e.Id] and not active[e.Id]
		for a in pairs(active) do
			if Events.Clash[a] and Events.Clash[a][e.Id] then ok = false end
		end
		if ok then
			local w = (e.Weight or 1) * (e.Id == boost and 2 or 1)
			table.insert(pool, { e, w }); total += w
		end
	end
	if #pool == 0 then return nil end
	local x = math.random() * total
	for _, it in ipairs(pool) do
		x -= it[2]; if x <= 0 then return it[1] end
	end
	return pool[#pool][1]
end
02 / TOWER DEFENSE

Tower Defense

A tower defense base I built as a separate project. Zombies walk a path toward the core, you place towers from a hotbar and they shoot whatever is in range. 20 waves with bosses on 10 and 20.

Placement

Ghost preview with a range circle that turns red on the path, near other towers or at the edge. The same rules run on the server, so the client can't cheat a spot.

Targeting

First, last, strongest or closest. Single target, splash, slow and poison damage, with upgrades up to level 4.

Light server

Enemies are invisible parts moved with one BulkMoveTo call per frame. Models, animations and health bars are only on the client.

Waves

Wave mix is generated from rules instead of a huge table: new enemy types unlock as you go, health scales per wave.

Units and rarity

8 towers from Common to Mythic, plus random traits like faster fire or extra range on top.

Match loop

Intermission, waves, breaks, vote to skip, game over when the core hits 0, then a clean reset.

How a tower picks a target

Each enemy only stores how far it has walked along the path, so "first" is just the biggest number. No pathfinding or extra lookups needed.

Distance is checked squared on X/Z to skip a square root for every enemy, every shot.

ServerScriptService/Services/TowerService.lua

local function findTarget(tower)
	local rangeSq = tower.Stats.Range ^ 2
	local mode = tower.TargetMode
	local best, bestScore = nil, -math.huge

	for _, enemy in EnemyService.Alive do
		local offset = enemy.Part.Position - tower.Pos
		local distSq = offset.X * offset.X + offset.Z * offset.Z
		if distSq <= rangeSq then
			local score
			if mode == "First" then
				score = enemy.Dist
			elseif mode == "Last" then
				score = -enemy.Dist
			elseif mode == "Strongest" then
				score = enemy.Health + enemy.Dist * 0.001
			else
				score = -distSq
			end
			if score > bestScore then
				best, bestScore = enemy, score
			end
		end
	end
	return best
end
